Telegram

Auto-sends the raw target dataset (JSON) to your bot whenever it changes.

Bundles everything Bjorn has collected — hosts and ports, HTTP fingerprints, web findings, SNMP, vulnerabilities, BLE devices, Wi-Fi APs and clients, and optionally cracked credentials — into one JSON document and delivers it whenever the contents actually change. Telegram is tried first; if it is unconfigured or blocked, email takes over. This is how you get results off a device you are not standing next to.

Manual — getting a bot, the email fallback, and when it sends

Setting up the Telegram bot

  1. In Telegram, message @BotFather and send /newbot. It replies with a token that looks like 123456789:AAE... — paste that into Bot token.
  2. Send your new bot any message (a bot cannot start a conversation with you), or add it to the group or channel you want reports in.
  3. Get the chat id: open https://api.telegram.org/bot<token>/getUpdates in a browser and read chat.id from the result. Personal chats are positive numbers; groups and channels are negative, usually starting -100. Paste it into Chat ID.
  4. Tick Enable auto-send, press Save, then Send test message.

Email fallback (SMTP)

Worth configuring even if Telegram works: the networks this device roams onto — hotel, café, corporate — often block one channel or the other, and the two fail in different places. Email is tried only when Telegram is unconfigured or its send fails.

Host / PortPort 465 connects with implicit TLS; anything else (typically 587) upgrades with STARTTLS. A server that offers neither is refused — the send fails rather than going out in the clear, since this report can contain cracked credentials and the login would expose your mailbox password. A plain LAN relay will not work here.
Username / FromAlso used as the sender address.
PasswordFor Gmail, Outlook and most large providers this must be an app-specific password, not your account password. Stored in plain text in shared_config.json — use a throwaway mailbox.
RecipientsComma-separated.

When it actually sends

Two gates, both of which must pass. First a content check: the dataset is hashed, and an unchanged hash means nothing is sent — so a quiet network produces no traffic at all. Second a rate floor, Min interval, below which it will not send even if the data did change. Sending happens during an idle window, so the real gap between reports is at least the interval and often longer.

Send data now ignores both gates and delivers immediately — use it to confirm the whole path end to end. Send test message only proves the channel works, and goes down whichever channel is configured.

Credentials. Include cracked credentials puts every password Bjorn has cracked into the document and hands it to a third party — Telegram's servers, or your mail provider and every hop in between. Leave it off unless you specifically need the credentials off-device, and never point it at a channel with other people in it.
