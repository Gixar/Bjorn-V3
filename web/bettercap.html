Bettercap

Checking…

Bettercap is a network attack framework that runs as its own service alongside Bjorn — the same arrangement Bjorn already has with nmap and nmcli. Bjorn talks to it over a local HTTP API and folds the hosts it discovers into the same netkb.csv everything else writes to. It is a second pair of eyes on the network you are already joined to: it sees hosts that never answer a port scan, because it watches ARP traffic rather than knocking.

Not installed by default. Nothing here does anything until you install bettercap and switch it on. ARP spoofing puts Bjorn in the middle of other machines' traffic — only use it on a network you own or have written permission to test.
Manual — setup, the two modes, and what to expect

Setting it up

  1. Install bettercap on the Pi (sudo apt install bettercap), or re-run install_bjorn.sh and accept the optional step — it writes the service and generates a password for you.
  2. Fill in the API URL, user and password so they match the service, tick Enable Bettercap, and press Save.
  3. The status line above should turn running. If it says unauthorized, the password here and the one in /etc/systemd/system/bettercap.service disagree.

The two modes

Passive recon
(default)		Bettercap watches the network and reports the hosts it sees. It transmits nothing at anyone. This is the safe default and is useful on its own — ARP-visible hosts show up without a single port being touched.
ARP spoofingTells other machines that Bjorn is the router, so their traffic passes through it. This is an active attack: it is noisy, it appears in any monitoring worth the name, and a mistake can disrupt the network for everyone on it. Off unless you turn it on deliberately.
Passive sniffRecords traffic that passes through. Only sees other machines' traffic when ARP spoofing is also on — on a switched network, without it, Bjorn sees only its own.

The settings

API URLWhere bettercap's REST API listens. Keep it on 127.0.0.1: this is where Bjorn sends the API password, and an off-device address means those credentials leave the Pi. Bjorn refuses to start with a non-loopback address while Bettercap is enabled.
User / PasswordMust match the api.rest credentials in the service file. Bettercap ships with a well-known default pair — if you set this up by hand, change it.
Monitor mode, deauthentication and handshake capture are a separate, later feature (the Handshake Hunter) and need a second radio. Nothing on this page touches the radio carrying Bjorn's own connection.

Handshake Hunter

Checking…

While Bjorn has no network, it can spend the idle time between reconnection attempts listening for WPA handshakes on a second radio, instead of simply waiting. Captures land in data/output/handshakes/raw/, one file per access point.

Needs a second radio, and refuses to run without one. Monitor mode takes a radio off the network entirely. On a single-radio device the hunter would hold the only way back online — Bjorn could never rejoin a network, and so could never deliver anything it captured. It also stops itself before every reconnection attempt, for the same reason.
