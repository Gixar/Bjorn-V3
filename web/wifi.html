Wi-Fi recon

Passive 802.11 survey via airodump-ng — logs nearby access points and their clients.

Puts a second radio into monitor mode and listens to raw 802.11 traffic for a fixed window, recording every access point it hears and which client devices are talking to each one. Purely passive — nothing is transmitted, no network is joined. Results land in wifi_aps.csv and wifi_clients.csv.

Manual — the second-radio rule, setup, and reading the results
This needs a USB dongle. A radio cannot be in monitor mode and connected to a network at the same time. Putting Bjorn's own uplink into monitor mode would kill the web UI, reporting and IP scanning at once — from inside the process that would have had to tell you about it. The interface carrying the default route is therefore refused, and shown greyed out in the dropdown rather than hidden. The check is on the routing table, not the name, so it stays correct when a dongle enumerates as wlan0.

Setting it up

  1. Plug in a monitor-mode-capable USB Wi-Fi adapter and reload this page — the dropdown is populated from the interfaces present right now.
  2. Pick the dongle. If only one entry is listed and it is greyed out, that is the uplink and the dongle has not enumerated.
  3. Press Test monitor mode first. It checks the guard and asks the radio whether it supports monitor mode, without capturing anything.
  4. Only once the test passes, tick Enable Wi-Fi scanning and Save. Results appear after the next idle window.

The settings

Capture durationSeconds per capture. airodump hops channels throughout, so a short capture simply misses APs on channels it did not reach — 30 s is a floor, 60 s+ finds noticeably more.
Min intervalFloor between captures. The radio is held for the whole capture, so a short interval means a nearly always-busy dongle.

Reading the tables

Privacy / Cipher / AuthThe AP's encryption. OPN is an open network; WEP is broken; WPA2/WPA3 are current.
PowerSignal strength in dBm — closer to zero is nearer. Roughly, above −60 is in the room, below −80 is through walls or outside.
Clients → BSSIDWhich AP that client is associated with. (not associated) means the device is searching rather than connected.
Probed ESSIDsNetworks an unassociated device is actively calling out for. These are names it has connected to before — often a home or workplace SSID, which makes them a useful fingerprint of where a device has been.
Rows merge by BSSID and station MAC across captures and keep their original first-seen, so the tables build a picture of the area over time rather than showing only the last capture. Many phones randomize their MAC while probing, so one device can appear as several client rows.

Requires a second radio. The interface carrying Bjorn's own connection is rejected — monitor mode on it would drop the web UI, reporting and scanning.
